## PR 9034 Zero new tokens must produce an empty delta

**Exact change.** At `22f8a69549d30b9b00464141797d274fb6b7e65f`, [lines 516–535](../experiments/vllm/fixtures/pr-9034/before/vllm/sequence.py#L516-L535) return all output IDs immediately for non-delta mode. Delta mode computes `n = output_len - previous_offset`, updates the offset, returns a scalar for `n == 1`, and otherwise slices `cached_all[-n:]`. With `n == 0`, Python's `-0 == 0` makes that the entire cache. This cache contains **prompt plus output**, per [lines 211–215](../experiments/vllm/fixtures/pr-9034/after/vllm/sequence.py#L211-L215), not merely earlier generated tokens. At `ba30942240d35eb26b503e139eb4b01ccbbeb954`, the [only change in this file](../experiments/vllm/fixtures/pr-9034/after/vllm/sequence.py#L516-L538) adds `if num_new_tokens == 0: return []` before the slice. The non-delta early return, offset update, and scalar case remain.

**Proposed narrow rule.** For this delta-output contract, exclude zero before interpreting a negated new-token count as a suffix length. Under an append-only, cache-consistent lifecycle with `0 <= previous_offset <= output_len`, zero requires no token IDs, one keeps the scalar optimization, and larger counts select exactly the new output suffix. A non-delta call returns all output IDs and does not advance this offset. These are static deductions, not executed results.

**Tempting overreach and legal neighbor.** “Negative slicing of token caches is erroneous” would reject the retained after-line-538 slice for valid `n > 1`. The zero guard alone does **not** prove safety for negative counts or inconsistent caches. Offset initialization [at line 441](../experiments/vllm/fixtures/pr-9034/after/vllm/sequence.py#L433-L442), normal append [at lines 266–269](../experiments/vllm/fixtures/pr-9034/after/vllm/sequence.py#L266-L279), and an output-replacement setter [at lines 242–246](../experiments/vllm/fixtures/pr-9034/after/vllm/sequence.py#L238-L246) are present; all callers and lifecycle invariants are not validated.

**Context and test limits.** The saved [PR patches](../experiments/vllm/evidence/pr-9034-summary.json) also change two serving files to skip initial empty chunks; those production files are patch-only. The retained [integration test](../experiments/vllm/evidence/pr-9034/after/tests/entrypoints/openai/test_chunked_prompt.py#L40-L126) exercises long-prompt completion/chat streaming, usage, and logprobs. It uses a model/server fixture (lines 8–31), was not run, and cannot isolate this method from the accompanying serving changes. No direct method test is retained. Issue #8988 is only a researcher summary.

**Research relevance.** The immediate bug is generic Python zero slicing; the delta contract and mixed prompt/output cache add repository meaning. Useful for H1's guard-sensitive explanation, weak as evidence that repository-specific learning is necessary. It supplies one repair, no observed rule revision, and no independent recurrence. A later date than #8568 does not make it a future target for that different rule. ## PR 2570 Optional max tokens is a small contract control

**Exact change.** The [before constructor](../experiments/vllm/fixtures/pr-2570/before/vllm/sampling_params.py#L111-L148), at `1e4277d2d1eceedbe0d00ba9e2c1bef88145df7b`, annotates `max_tokens: int = 16`, assigns it unchanged, and invokes `_verify_args`. Its [unguarded comparison at line 186](../experiments/vllm/fixtures/pr-2570/before/vllm/sampling_params.py#L183-L194) reaches `None < 1` when earlier checks accept the other arguments. At `3209b4903376fd723858b256dcfabb8420a0cc64`, the annotation becomes [optional](../experiments/vllm/fixtures/pr-2570/after/vllm/sampling_params.py#L111-L116) and the comparison becomes [`self.max_tokens is not None and self.max_tokens < 1`](../experiments/vllm/fixtures/pr-2570/after/vllm/sampling_params.py#L183-L194). The short circuit avoids that comparison for `None`; nonpositive integers still take the `ValueError` branch.

**Proposed narrow rule.** Where this API admits `max_tokens=None`, bypass its numeric lower-bound comparison for that sentinel while retaining the lower bound for supplied integers. This does not require guarding every numeric field or accepting arbitrary non-integer inputs.

**Tempting overreach and legal neighbor.** “Every accepted `max_tokens` value must be at least one” wrongly excludes `None`, explicitly admitted by the [direct test at lines 6–8](../experiments/vllm/evidence/pr-2570/after/tests/test_sampling_params.py#L6-L8). Conversely, skipping validation for all falsey values would also skip zero, which the retained comparison rejects. Positive integers remain compatible with this check. These are same-contract input contrasts, not additional real cases.

**Context and test limits.** The [saved PR body](../experiments/vllm/evidence/pr-2570-summary.json) reports a regression of previously allowed `None`; the before annotation alone would suggest a narrower domain. The direct test declares constructor acceptance; the [generation regression test, lines 25–35](../experiments/vllm/evidence/pr-2570/after/tests/test_regression.py#L25-L35), uses `facebook/opt-125m` and checks output count. Neither ran. The retained bytes do not reconstruct the earlier contract/history or establish the downstream meaning of `None`, such as unlimited generation.

**Research relevance.** Keep this as a weak/control case: a generic optional-value comparison bug with a repository API admission fact. It may test whether an explanation respects a declared sentinel, but offers little evidence that sophisticated repository memory or diagnosis is needed. It weakens an all-cases-need-rich-context narrative. The annotation repair is not evidence of a historical contract change or review-rule update, and no later same-rule target is established.
