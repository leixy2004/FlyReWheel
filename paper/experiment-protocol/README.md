# Research packet specification

These are authoring templates for the selected [one-repository three-window experiment](../discriminating-experiment.md), reconciled at checkout `250a242` on 2026-10-02. W0 rules are generated experimentally from earlier real PRs and frozen before W1 exposure; independent humans verify actual W1 review findings as experimental feedback; W2 independent later PRs compare F/U/H/M under matched conditions. The route is selected, but operational fields are not yet frozen or preregistered. No model call, generated rule, new case or independent human label is supplied. This is not an executable FlyReWheel API.

- `prompts.md` separates W0 construction, W1 review/feedback, diagnosis, common revision, hard/unrestricted/memory policies, common review, and blinded W2 assessment
- `record.schema.json`, version `paired-restriction-v2-temporal-draft`, records all-PR source-frame rows, all W0 construction attempts, exposure locks, screening, paired episodes and outputs without invented observations
- [SDK-native configuration amendment](sdk-native-study-amendment.md), version `paired-restriction-sdk-native-v1-draft`, specifies a proposed separately versioned profile for the installed SDK: supported native settings, byte/time/call enforcement, observed token/unknown-cost accounting and repeated randomized blocks. It is not implemented or frozen; the existing schema and unsupported-control preflight remain unchanged and fail closed

## Freeze and provenance requirements

Use opaque output IDs for assessors and keep arm mappings separate until assessment is locked. Fill placeholders from verified evidence and hash rendered prompts and source packages. Enclosed source prose is data, not instruction. Source timestamps, public visibility, acquisition timestamps and actual experimental generation/lock/exposure times are distinct.

1. Freeze the one-repository W0/W1/W2 frame, dates, complete enumeration, selection rule/counts, seed where applicable, missingness handling, cost/annotation budget and stop rule before formal outcome inspection. Earlier 90/180, 10/20 and eight-family sketches are not active numeric requirements
2. Preserve every W0 construction attempt, including unsupported/no-rule/failed outcomes, then lock exact supported rule bytes and the family roster before W1 content enters construction or W1 labels are available to it. Do not claim these generated rules historically existed
3. Preserve actual W1 input/output traces. Independently human-verify experimental feedback and diagnosis, including unknowns, before updating; no W2 evidence is permitted. Natural developer feedback is optional supporting evidence or a separately identified natural cohort, not a mandatory gate
4. Retain every in-frame PR and every sampled W1/W2 PR × frozen-family pair, including zero opportunity, no finding, missing checkpoint, unknown, failed and not-run cases. Record lineage independence, issue grouping and the selection funnel into the paired effect cohort
5. Lock shared feedback, O/I diagnosis conditions, one-proposal policies, common gate, model/resource settings, target roster, W2 reference labels and analysis before arm outputs. Keep all rejected/non-mutation effective states in evaluation. Cross-category claims require all supported strata; lack of a stratum narrows the claim rather than blocking feasibility or inviting fabrication

The schema's `draft` status permits an unfinished empty record. `frozen` refers to the final method-run freeze after the separate frame, W0 and W1 locks. It requires filled structural fields; JSON validation cannot prove chronological inequalities, exact roster completeness, independent annotations, as-of visibility, absence of W2 exposure, matched budgets or semantic correctness. Those require documented human audit. In particular, check rule lock < first middle-content exposure and rule lock < first middle-label availability; never backdate either event. Public-pretraining contamination remains a disclosed limitation.

The selected primary origin is `generated_rule_temporal`; `natural` is an optional separate-origin supplement, never a substitute for the generated-rule cohort or an inferred historical claim. Synthetic development fixtures do not enter either empirical cohort. The schema includes no nonempty dataset or purported example annotation.
