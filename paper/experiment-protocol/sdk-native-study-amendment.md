## 2. Resource and isolation contract

The native profile matches **enforceable byte, call and elapsed-time ceilings**, not a claimed fixed number of generated tokens or fixed spend. Freeze numeric limits and counting rules before outputs; none are selected here.

- Bound serialized request/schema bytes before launch; separately bound the UTF-8 bytes of the rendered persistent state, proposal answer and review answer. Count M's retained initial lesson, delta and rendering overhead against the same total state allowance as U/H. Freeze serialization and count actual bytes, without renaming the fixture byte counter a model tokenizer
- Preserve supervisor limits on raw stdout/stderr and forwarded/event bytes, a per-call deadline, bounded cancellation/cleanup and verified process termination. These stream limits include protocol/reasoning/progress overhead and differ from the final-answer/state limits. Declare both. Oversized or late answers are failures, not truncated valid proposals
- Bound dispatched attempts per role/arm and remaining arm execution time, including the allocated shared diagnosis. Freeze whether setup and cleanup are included in each timer and report their durations separately. One proposal slot still includes failed or invalid proposals; no retry or favorable reroll. Provider-internal calls/retries must be disabled or separately recorded and budgeted: one SDK invocation is not automatically one billable model call
- Report SDK usage **after** execution: input, cached input, cache-write input, output and reasoning-output tokens, preserving raw field names. These fields are not assumed disjoint and must not be naively summed. Missing usage, aborted calls and undocumented billing semantics remain unknown. A postflight token threshold, if separately selected, is an admission/stop rule with possible overshoot, never a generation cap or refund
- The SDK reports no currency. Keep monetary cost unknown unless supported by an authoritative billing record; label price-based estimates separately with their assumptions. Never turn null into zero or infer a spending guarantee from observed tokens, elapsed time or output bytes. Report physical shared-diagnosis cost once and its standalone allocation once to each U/H/M policy; F has no maintenance charge. Partial totals are labeled known lower bounds and cannot establish cost dominance

**Monetary permission is a separate launch gate.** A requested hard spending ceiling requires an independently enforceable provider/gateway mechanism, including in-flight reservations and stop/overshoot semantics. If that guarantee is unavailable, do not dispatch under that ceiling. Any alternative monetary exposure needs explicit authorization and a disclosed stop/reconciliation policy before billable work. This draft grants neither. Unknown-cost reporting is not permission for unlimited spending; it does not relax today's unknown-usage dispatch blocker.

The [worker](../../src/adapters/codex-workspace-worker.ts) disables tool features, uses fresh homes, rejects ambient project configuration and rejects tool events. These checks and read-only settings do not prove containment: an observed forbidden event may already reflect an attempted action. A trusted isolated runtime must enforce selected-input visibility, no outside retrieval, restricted provider-only egress, credential separation, resource bounds and whole-runtime stop/destroy verification. The current process-group receipt is weaker than that guarantee. Record SDK policy, application checks and externally verified isolation as three distinct kinds of evidence. Local abort also does not prove remote generation/billing stopped.

## 3. Fairness and stochastic variation

Keep the original scientific contrast unchanged: F retains the incumbent; U/H share the neutral structured envelope; only H receives diagnosis-conditioned operator prohibitions; M has competent, bounded family-local memory with no free transcript. All updating arms receive byte-identical evidence, feedback and the same locked diagnosis, with matched role-specific settings, visibility, ceilings and gate G. All arms review the same scheduled future targets, including rejected proposals, abstentions and failures. Same-G acceptance and immutable labels, evidence identities and regression obligations remain mandatory. Gate-selected old-positive performance is not heldout evidence.

Replace **generation-seed matching** with a frozen repeated-block design:

1. Freeze repetition count R, block identifiers, scheduling/randomization algorithm and its local scheduling seed before method outputs. Use multiple repetitions to measure run variation; an R=1 feasibility pass cannot estimate it. The scheduling seed reproduces assignment/order only and is never passed off as a model seed
2. Each episode × diagnosis condition × repetition starts from the same locked incumbent in fresh contexts. O reuses the locked independent diagnosis; I performs one diagnosis-only attempt per episode/repetition, locks that output once and shares it with U/H/M. Preserve administrative failure behavior, with no diagnosis retry. Do not resample diagnoses separately by arm
3. Within each block, randomize/counterbalance F/U/H/M execution order and O/I block order while respecting diagnosis → proposal → G → future dependencies. Freeze the target order shared across arms within a block; randomize it across blocks. Keep comparable calls temporally close and record actual order, timestamps and interruptions to expose provider/load drift
4. Use one gate attempt and the fixed future schedule for each arm/repetition. The native profile uses independent fresh calls even when effective states coincide; no output cache reuse or best-repetition selection. Provider-side prompt caching may still occur: report observed cached usage and do not claim it was eliminated
5. Analyze H−U and H−M within the same episode/condition/repetition and roster. Report all repetitions, raw gains/losses, gate acceptance, failures and between-run variation; never choose the most favorable run or add repetitions after seeing effects. Keep O/I separate and preserve PR/family/lineage clustering; repeats of one episode are not new independent episodes. Freeze aggregation, uncertainty and missing-run rules before outcomes

Pairing therefore means matched inputs and schedules, **not common random model draws**. Randomized order and repetitions reduce or reveal some stochastic/time effects but do not guarantee determinism or eliminate drift. Model-token efficiency and monetary superiority remain unavailable when measurement is inadequate. Equal byte budgets are an explicit representation constraint, not equal tokenization or equal actual compute; report those limits when interpreting H/U/M differences.
