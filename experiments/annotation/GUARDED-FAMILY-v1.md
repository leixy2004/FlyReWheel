## Frozen family and opportunity

The existing rule's invariant is “An applicable guard protects a danger call.”
The versioned specification binds its full rule digest/semantics, one family,
rubric text/digest, annotation plan/dataset and source snapshots. Candidate scope
must cover each opportunity's repository and path. Scope matching is not proof
of semantic applicability. Changing semantics requires a new measurement version;
a rehashed different applicability statement cannot reuse this one.

One opportunity is `(after-snapshot, family, operation issue, exact code span)`.
It is declared before evaluated outputs. Multiple evidence citations do not create
extra instances; one issue with multiple anchors remains one opportunity. The
current matched `TargetInput` has one interval, so the route checker blocks a
multi-anchor opportunity rather than truncating it or inflating the denominator.
The frozen roster includes every chosen opportunity and its coverage, including
missing work. This is neither an exhaustive discovery procedure nor a formal
changed-surviving-line claim.

Required context is the operation's source-bound dangerous-effect contract, the
guard's source-bound protection contract, relevant value identity, control flow
and possible invalidation between guard and operation. A textual `guard` before
`danger` alone cannot prove protection, path coverage or applicability. The existing
fixture rule's empty `requiredContext` field is not permission to infer real
semantics; a substantive source/context audit is still required before any real
family adoption. This version never admits real adoption.

## Source truth, coverage and finding feedback

| Record | Evidence required | Prohibited inference |
| --- | --- | --- |
| Positive source opportunity | Applicable dangerous operation with a supported feasible execution lacking the required protection | Version changed, test missing, or token `danger` appears |
| Negative source opportunity | Assessed applicability and supported satisfaction, or a separately evidenced non-applicability premise | No alert, passing linter, or unseen behavior is safe |
| Unknown source opportunity | Work was performed but an applicability, contract, path or context premise cannot be resolved | Convert unperformed work to an Unknown instance |
| Disputed source opportunity | Substantive conflict remains after independent adjudication | Force agreement or select a favorable rater |
| Missing/unassessed | No valid completed judgment for that opportunity | Count as negative, Unknown, or drop from coverage |
| Excluded | Explicit predefined scope violation with reason | Score as a legal neighbor or remove silently |
| TP finding feedback | An actual locked reviewer finding under the frozen rule, at the same source/issue scope, independently confirmed by positive evidence | Convert a source-positive label into a finding that never occurred |
| FP finding feedback | An actual locked finding independently shown unsupported/wrong at that exact scope using adequate source context | Convert every source-negative label into FP or use current discussion as historical feedback |
| Unknown finding feedback | A real finding exists but correctness cannot be resolved | Assume FP because its premise is uncertain |
| Missing finding record | No returned reviewer record/finding eligible for assessment | Fabricate a finding, TP/FP or independent supervision |

The existing source-only annotation workflow handles source truth and coverage.
It does not expose reviewer findings to source raters and does not implement the
separate finding-correctness stage above. That stage remains a named admission
gate, not a fabricated event or generic feedback adapter.

## Source/time and independent judgment admission

Use the declared current-capture development snapshot and common source allowlist,
with actual capture, plan freeze, exposure, submission/import and adjudication times
kept distinct. Snapshot/source hashes and capture-record digests bind exact bytes;
they do not prove historical public visibility. Historical as-of reconstruction is
an additional requirement only if that optional claim is later pursued. Do not
substitute merge time for a public review checkpoint or put an edited current
comment at its original creation time.

Both source raters receive identical source/rubric bytes without method-arm IDs,
outputs, outcome explanations, original PR identity metadata or peer responses.
Two distinct declared identities lock full submissions before a third distinct
adjudicator sees anonymous A/B judgments and the same source. A missing rater
blocks adjudication. The adjudicator may accept a supported judgment or retain
Unknown/disputed; both missing judgments must remain unassessed. Context changes
require a new shared packet and independent restart, preserving the original locks.
Pre-adjudication agreement and coverage are reported separately. Public source and
free text can reidentify cases; declarations do not authenticate human independence.

No human is assigned or simulated as a real participant here. Authored fixtures
remain synthetic. HTTPX before-only drafts retain their prior blocked status; the
new fixture rubric is not attached to them to manufacture a usable real family.

## Predeclared H2 route and its current stopping point

1. Freeze a defensible W0 rule and complete source/failure roster before W1 exposure.
2. Retain the actual W1 common-review finding and independent TP/FP/Unknown assessment,
   then lock the common feedback, diagnosis and gate. Do not infer these from source labels.
3. Independently assemble W2 positive and legal-neighbor opportunities, excluding
   extraction, W1, gate, repair, duplicate and backport lineages. Different synthetic
   target IDs are not empirical independence evidence.
4. Lock a source-supported subtype for each negative **before arm outputs**:
   `safe_applicable` means the rule applies and the invariant holds;
   `legal_neighbor` requires an independently supported applicability/exception
   boundary despite the rule's surface trigger. A protected operation does not
   automatically become a legal neighbor merely because its source label is negative.
5. Separately adjudicate whether each legal neighbor belongs to the frozen W1
   feedback mechanism (`L_mech`). Bind the mechanism definition, index finding,
   exact target and adjudication records. Missing membership is not boolean false.
   Unknown/disputed references retain unresolved membership instead of receiving
   invented classification. This judgment cannot consult H/U/M/F results.
6. Only after complete lossless binding create `FrozenFuture`, then use the existing
   `freezeAuthoredEvaluationContract`/`validateEvaluationContract` plumbing for
   authored checks. A real adapter still needs the existing real-study admission
   gates. The current contract is authored-only, not a real-run authorization.

`inspectGuardedLabelRoute` currently stops **before step 6**. It validates exact
rule/family/plan/annotation/target-source binding and preserves every opportunity.
Positive, Unknown and disputed can have provisional same-meaning labels only when
scope is exact and no missing target context is declared. Negative subtype,
excluded/missing rows, multi-anchor scope and unjudged mechanism membership stay
blocked. `matchedFuture` is always null. There is no partial cohort, guessed false
membership, automatic TP/FP conversion or reuse of the old runner fixture's
handwritten `legal_neighbor` label as independent annotation truth.

For an eventually admitted study, preserve the paper's H−U repeated-mechanism false
alarm endpoint with positive recall, strict legal-neighbor resolution and coverage;
H−M remains a practical comparison. No-alert/abstention is not strict resolution.
Zero required denominators are not estimable. This work reports no effect or interval.

annotations, not authentication of the human workflow's lock records. Its authored
origin restriction and unconditional blocked result prevent empirical promotion.
